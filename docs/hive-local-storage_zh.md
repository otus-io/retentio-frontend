# 本地优先学习（Hive）— v1

学习 / 复习始终在设备端进行。**导入**后，该卡组的 **全部词条与媒体** 都下载到本地设备；卡片调度保留在本地。

英文版：[hive-local-storage.md](hive-local-storage.md)

| 数据 | 真相来源 |
|------|----------|
| 卡片（`dueDate`、`lastReview`、`hidden`、template） | 设备 |
| 词条、媒体文件 | 服务端 → 向下同步 |
| 卡组元数据（name、fields 等） | 编辑时以服务端为准；本地缓存 |

---

## 1. 导入卡组 → 本地下载全部数据

**导入成功**（目录 / 分享导入 API）后，将该卡组的 **全部词条** 与 **全部引用媒体** 下载到本地（Hive + 应用文档目录），以便离线学习。

```text
导入成功（在线）→ 得到导入卡组 id
  → 在 local_decks 中缓存卡组元数据
  → 分页拉取全部词条 → local_facts
  → 下载全部引用媒体 → 应用文档目录
  → 为可学习词条初始化 local_cards（仅首次：可采用服务端 card id / 初始 dueDate）
  → 标记卡组本地就绪（syncedAt）
```

**已有导入卡组的存量用户：** 登录 / 启动且在线时，找出尚未完整落地的导入卡组，在后台 **自动下载**（流程同上）。展示进度；就绪后学习只使用本地数据。自有（非导入）卡组默认仍按用例 3 按需拉取，除非产品后续要求同样自动下载。

这是 **首次全量拉取**。之后内容更新仍走用例 3（且不得覆盖本地调度）。作者发布 → 导入者 `POST …/sync` 仍是独立的在线分享流程；该 sync 成功后再对该卡组执行用例 3（或全量重拉）以更新词条 / 媒体。

---

## 2. 复习卡片（始终本地）

```text
打开学习 → 从 local_cards 取下一张到期卡（+ 词条/媒体用于展示）
评分 / 隐藏 → 更新 local_cards → 追加到 review_outbox → 下一张
点击时不调用 GET/PATCH …/card
```

若卡片、词条（及媒体）已同步到本地（用例 1 或 3），即可离线学习。

---

## 3. 从服务端同步（仅词条 + 媒体）

只拉取 **词条与媒体**。**不要**从服务端下载卡片调度 / 卡片载荷（不以 `GET …/card`、cards 列表等作为调度来源）。

```text
下拉刷新 / 恢复前台 / 打开过期卡组（在线）
  → 若在线：先执行用例 5（刷写 review outbox / 待同步队列）
  → upsert local_facts（+ 卡组元数据缓存）
  → 下载引用的媒体到应用文档目录
  → 若词条有增删：在本地增删对应的 local_cards 行
       （保留已有 dueDate/lastReview；不从服务端取调度）
```

本次同步不包含：任何服务端 **卡片** 数据作为真相来源、导入用的 `POST …/sync`、用服务端复习历史替换本地。

**若内容拉取发生在刷写之前：** 本地调度保持不变（设备为真相来源）。未刷写的 `review_outbox` 条目仍保留，稍后继续刷写。唯一风险是远端删除词条导致本地卡片行被增删——因此在线时应先刷写；词条同步后，丢弃 `cardId` 已不存在的 outbox 行。

---

## 4. 编辑卡组 / 词条（仅在线）

```text
在线：沿用现有 API → 成功后对该卡组执行用例 3
离线：禁用新增/编辑/删除卡组与词条（提示「当前离线」）
```

无离线编辑队列。发布 / 导入 / 贡献流程与现网一致，仍仅在线。

---

## 5. 将卡片复习同步到服务端

每次复习立即写入 Hive + `review_outbox`（用例 2）。以 **批量** 方式推送到服务端，而非每次点击都推送。

| 触发条件 | 原因 |
|----------|------|
| 待同步队列达到 **N** 条复习（v1 默认 **N = 100**） | 复习多次后再传 — 减少学习过程中的 HTTP |
| 用户 **离开学习**（退出路由 / 结束会话） | 短会话不必等到 N |
| 应用 **进入后台** / 再次 **回到前台** 且在线 | 进程被杀前的兜底 |
| **网络恢复** | 刷出离线期间积压的队列 |

```text
在线刷写 → 按 FIFO 对 outbox 每行调用 CardService.updateCard → 成功则删除
绝不因网络阻塞复习界面
```

v1 **不在**用户正在学习时用定时器刷写（避免卡顿）；达到 N 或结束会话即可。

## 对照表

| 操作 | 在线 | 离线 |
|------|------|------|
| 导入 → 全量本地下载（1） | 是（必须） | 无法导入；若已下载则用本地 |
| 存量导入卡组自动下载（1） | 登录/启动时后台 | 等上线后再拉 |
| 复习 / 下一张卡（2） | 本地 | 本地 |
| 同步词条 + 媒体（3） | 是 | 使用上次本地内容 |
| 编辑卡组 / 词条 / 上传媒体（4） | API → 再用例 3 | 禁用 |
| 刷写 review outbox（5） | 后台批量 | 排队 |

## 存储

| 存储 | 内容 |
|------|------|
| `local_decks` / `local_facts` / `local_cards` | 元数据、内容、调度 |
| `review_outbox` | 待推送的复习 PATCH（用例 2 写入，用例 5 刷写） |
| 媒体文件（documents 目录） | 按 media id 存字节 |

按用户隔离；退出登录时清除。仅新建 Hive box — 不写入 `hydrated_box`。

**代码：** `LocalDeckStore` + `ContentSync`（1、3）+ 本地 `DeckStudyRepository`（2）+ 离线 UI 门禁（4）+ outbox 刷写器（5）。

---

## 实现顺序

1. 用例 1 导入 + 存量导入卡组自动下载 → 验证整卡组落地  
2. 用例 3 词条/媒体同步 → 验证离线内容刷新  
3. 用例 2 本地学习 + 写入 outbox → 验证阻断 card HTTP 时会话仍可用  
4. 用例 5 刷写 outbox → 验证服务端收到复习  
5. 用例 4 离线门禁 + 编辑后走用例 3  

**可接受的折中：** 本地到期顺序不必与服务端 urgency 完全一致；首次大卡组同步 / 导入下载需进度提示；多设备 / 电脑见下文；内容拉取不得覆盖未刷写的本地调度。

## 多设备与电脑（Web）

### 两台手机 / 平板，同一账号、同一卡组

| 情况 | v1 行为 |
|------|---------|
| 词条 / 媒体 | 两端都可拉取同一内容（用例 1 / 3） |
| 复习 | 每台设备各自维护 `local_cards` + outbox，直到刷写（用例 5） |
| 冲突 | 服务端上每张卡以最后一次成功的 `PATCH …/card` 为准。另一台设备 **不会** 因内容同步而重拉调度（设计如此）。因此设备 B 的本地到期可能与服务端、与设备 A 不一致，直到以后再做「采纳服务端调度」 |

**v1 产品立场：** 主要在一台设备上学习、并经常刷写（离开学习 / N=100 / 恢复网络）时可用。两台设备同时大量复习仅为 **尽力而为** — v1 不做合并 UI。

### 电脑（Web / 桌面）

本文针对 **Flutter App**（设备上的 Hive）。`retentio-webapp` 不共享该 Hive。

| 方案 | 含义 |
|------|------|
| A（v1 默认） | Web 仍用 **服务端驱动学习**（现有 `GET/PATCH …/card`）。手机保持本地优先。同一账号可能分歧：Web 更新服务端调度；手机内容同步忽略调度 |
| B（后续） | Web 自有本地库（如 IndexedDB）+ 相同 outbox 规则 |
| C（后续） | 手机在 Web 学习后可选「从服务端拉一次调度」以对齐 |

在 B/C 落地前，建议 **以一台设备为主学习**，或接受：Web 上的复习不会自动改写手机本地队列。
