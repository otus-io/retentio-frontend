# 词条、标签与协作

🌐 [English](knowledge_base_content.md) · [知识库](knowledge_base_zh.md)

词条是卡组里的一行内容。卡片是服务端按模板从词条切出来的学习面。标签用来给词条分组，并缩小学习队列。导入者在自己的副本上改内容，再手动把改动交给作者；作者在收件箱里接受或驳回。

## 词条和卡片怎么对应

一个词条有 `id` 和 `entries`。每个 entry 可以有 `text`、`audio`、`image`、`video`、`json`。行数默认等于卡组列数；卡组没有列名时，添加界面固定两行。

添加请求不传 `template`，也不传列名。常见结果是服务端做成一张卡：正面用第 0 个 entry，背面用其余 entry。客户端未证实这是唯一模板。模型允许一个词条多张卡。

学习时看到的正反面是卡片上的槽位，由服务端填好，不是客户端临时用词条拼出来的。

## 添加词条

入口在学习页菜单。每一行至少要有正文或一个附件，否则不能提交。录音中不能提交。

每行最多各一个图片、视频、音频。选文件时预检：图片 5 MB，音频和视频 200 MB。类型不对或文件不存在则不上传。

提交时：

1. 本地文件先 `POST /api/media`，把返回的媒体 id 写进 entry。
2. 可选带上 `tag_ids`。
3. `POST /api/decks/{id}/facts/append`。排序方式写死 append。
4. 成功后刷新卡组列表，并按需要刷新学习队列，表单清空。

接口错误文案认识 `prepend`、`shuffle`、`spread`，界面不能选。也没有计划文档里的动态增删行。

若当前是导入副本，提交前后会对比词条 id 列表，把新 id 记成一条 `add` 待贡献，并提示已放出发件箱。副本上的词条已经立刻存在；交给作者是另一步。

## 编辑、隐藏、删除

编辑入口在卡片菜单，按当前卡的 `factId` 打开。加载词条、卡组列名和词条标签。行数至少是卡组列数；词条 entry 更多时，多出来的行保留。

保存会上传新的本地媒体，再 `PATCH` 词条的 entries。列名只在和 entries 等长时一起提交。标签差异在保存成功后单独同步，失败不回滚词条正文。导入副本上，这次编辑会再写一条 `edit` 待贡献；标签有变化则另写一条 `factTags`。

| 动作 | 删掉什么 |
| ---- | -------- |
| 删除卡片 | 只删当前这张卡 |
| 隐藏卡片 | 不删。这张卡退出学习队列 |
| 删除词条 | 没有这个入口 |
| 删除卡组 | 源卡组未发布，或导入副本，可以整组删除。已发布源卡组不行 |

卡片菜单不检查是不是作者。谁能改由接口决定，客户端未证实只读副本会被拒。

## 注音标记

正文可以写 `[[汉字|读音]]`。编辑器可以把选区包成这种形式，读音或正文可以暂时空着。学习时若文本像这种标记，读音显示在字的上方；否则就是普通文本。正反面和注音的字号可以按卡组单独调，存在本机。

实现见 `lib/utils/wiki_ruby_markup.dart`。`docs/card-text-markup.md` 若与代码不一致，以代码为准。

## 标签

标签属于用户，可以挂在卡组或词条上。

| 挂在 | 在哪操作 | 对学习的影响 |
| ---- | -------- | ------------ |
| 词条 | 添加或编辑词条时 | 学习页筛选条只用这类标签。选中后只取带该标签的到期卡 |
| 卡组 | 创建或编辑卡组时 | 不进入学习筛选。会出现在目录信息里 |

添加词条时，`tag_ids` 随 append 一次提交。编辑词条时，标签是保存后再增删。

导入副本上修改卡组标签，会变成 `deckTags` 待贡献，不直接改作者的卡组。

资料页可以打开标签管理：创建、改名、删除。

## 贡献

两条角色：

- 导入者改的是自己的副本，改动立即生效。待提交项存在本机 `retentio_pending_contribs_v2:{deckId}`。同一类、同一个词条会互相覆盖。发件箱里勾选后才请求接口。成功的项进入已发送历史，最多 200 条。
- 作者在已发布源卡组上打开收件箱，只拉 `open`。可以接受、驳回（`dismissed`）或标为已处理（`resolved`）。接受之后列表重载。

| 种类 | 导入者怎么产生 | 作者能接受吗 |
| ---- | -------------- | ------------ |
| `fact_add` | 在副本里新增词条 | 能 |
| `fact_edit` | 在副本里改词条 | 能 |
| `fact_tags` / `deck_tags` | 改词条标签或卡组标签。发件箱里用的是标签名 | 能 |
| `report` | 卡片菜单直接提交，不进发件箱 | 不能。只能驳回或标已处理 |
| `field_rename`、`template` | 模型里有，发件箱不能提交 | — |

举报只在导入副本的卡片菜单出现。类别是音频、内容、其他。选「其他」必须写说明。合成一条 message，最长 200。作者在收件箱里看到说明和词条预览。

待提交队列不是事务。进程在「标成已发送」中途被杀掉，可能丢掉还没标完的项。

## QA

只有导入副本的菜单里有 QA。它不走学习的间隔队列，而是按词条 id 列表线性往下走。

每一列可以勾选。能打分的列是这一列上文本或音频非空的面。勾选会 `PUT` 整份质量表：勾上的面写成人工 10 分，取消勾选会撤掉人工分。全部可打分列都勾上，或这一条没有可打分列，才能前往下一条。

QA 里编辑词条，会立刻提交一条 `fact_edit` 贡献，并把本地对应的待贡献标成已发送。

质量接口只给 QA 用。学习队列不看分数。
