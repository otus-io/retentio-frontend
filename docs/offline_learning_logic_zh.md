# 离线学习业务逻辑

英文版：[offline_learning_logic.md](offline_learning_logic.md)

本文只描述**当前已实现**的离线学习规则。设计背景、接口字段和存储形状见 [offline_learning_cache_plan_zh.md](offline_learning_cache_plan_zh.md)。代码在 `lib/features/offline_learning/`。

已下载的卡组在本地出卡、记复习。进度先记在本机，再按规则上传。未下载的卡组仍走在线接口。

## 范围

支持：

- 下载卡组后离线打开、翻面、复习、隐藏。
- 用已缓存的词条标签筛选。
- 卡组列表在离线时只显示已下载卡组，统计用本地结果。
- 把复习和隐藏上传到服务端，并回写复习次数。

不支持：

- 离线新建、编辑、删除卡组或词条。
- 离线上传媒体、导入或同步共享卡组。
- 离线删除卡片（删除必须先在服务端成功）。
- 下载视频和 JSON 媒体。

## 账号

离线数据按登录用户名分开。本机还没有用户名时，在线拉取个人资料并记住；离线又认不出账号时，不启用离线，学习与列表都走在线接口。

登出后换账号，看不到上一账号的卡组和待上传记录。

## 下载

一次下载成功后，卡组才算可离线学习。中途失败则保持未就绪；已经就绪的卡组，刷新失败也不撤销就绪状态。

触发：

- 发现页导入成功后，后台下载**导入后的卡组**。导入不等待下载，下载失败不影响导入结果。
- 进入该卡组学习页时下载；已就绪的卡组最多每小时刷新一次。有媒体文件下载失败的那次刷新不算数，下次进入会再刷新。
- 在学习页新增或编辑词条后，在后台刷新该卡组：下一张卡立刻用当前副本显示，刷新完成后再重绘。正在跑的下载可能在编辑之前就拉完了列表，所以这次刷新会排在它后面重新跑，不和它合并。
- 已登录时，主界面只上传进度，不会把全部卡组重新下载一遍。

每次下载：

1. 更新卡组名称、字段、速率、来源信息和复习次数。已有标签保留。下载期间若上传已刷新过次数，则保留那份更新的次数。
2. 分页拉取全部词条并覆盖同 ID 词条。卡组在分页期间变动时分页可能漏掉词条，所以删除依据完整的词条 ID 列表：不在列表里的本地词条才删除；读不到该列表则不删任何词条。
3. 用服务端调度覆盖每张卡片，有未确认本地改动、待上传记录，或在拉取卡片列表期间被本地改过的卡片除外。服务端已不存在的卡片会被删除，例外相同（待上传记录收到 404 时再删卡）。
4. 下载词条上的音频和图片。已有文件跳过；单个文件失败只记日志。视频和 JSON 不下载，学习时仍指向网络地址，离线打不开。

同一卡组的并发下载合并成一次。

删除卡组或清空账号数据前，先让正在跑的下载在下一步停下（丢掉写了一半的媒体文件）并等它结束；删除完成前不会开始新的下载。否则下载结束时会把卡组重新写成就绪。

## 卡组列表

- 在线：显示服务端列表。已下载卡组的统计换成本地计算（见「统计」）。
- 离线：只列出已下载卡组。
- 网络看起来可用但服务端不可达：已有下载则列出这些卡组；一张都没有则列表报错。
- 离线库打不开：退回服务端列表。
- 服务端删除成功后清掉该卡组的本地副本和不再被其他卡组使用的媒体。本地清理失败不推翻删除结果。删除被拒绝时保留本地副本。

离线时不轮询、不显示共享卡组的更新红点。

## 学习

进入学习页时决定这张卡组用本地还是在线，**本次停留不再切换**。在线进入后下载才完成的，要重新进入学习页才会改走本地。离线且没有本地副本时，每次出卡都会重新检查，期间下载完成的副本会被采用。

| 进入时 | 行为 |
| --- | --- |
| 已下载 | 本地出卡。在线时后台仍会刷新词条、媒体和卡片（见「下载」）；有本地改动的卡片保留自己的调度。 |
| 未下载且在线 | 走在线下一张卡接口。 |
| 未下载且离线 | 提示先联网下载，不出卡。 |

点下一张后界面立刻用本地结果更新，不等待上传。

标签：在线时刷新并缓存该卡组标签；在线结果为空（含请求失败）则沿用缓存。离线只用缓存。筛选只保留带该标签的词条所对应的卡片；筛完没有卡时显示空筛选，而不是「需要下载」。

出卡只使用本地仍能对上词条的卡片。正面、背面由卡片模板、词条和卡组字段当场拼出，不另存一份展示稿。音频和图片优先用本地文件，没有则用网络地址。

## 出卡规则

与后端 `GetNextCard` 同一套：

- 跳过已隐藏的卡，以及间隔（到期时间 − 上次复习）≤ 0 的卡。
- 紧急度 = 已经过的时间 ÷ 间隔，按 32 位浮点计算。
- 紧急度高的先出；相同则 ID 较小的先出。
- 同时预取排序后的下一张，供界面提前准备。
- 若上次复习时间在未来，先把它钳到现在，间隔不变，再参与排序。

复习：上次复习取「请求时间」和「现在」中较早的那个，新到期时间 = 上次复习 + 间隔。隐藏：只把该卡标为隐藏。两种操作都立刻写入本地，并各追加一条待上传记录。复习和隐藏不写在同一条请求里。

## 统计

已下载卡组的这些数字在本地重算，复习或隐藏后马上变：

- 卡片数、词条数、未学习、已复习、到期、隐藏、今日新卡、最近复习时间。
- 未学习：未隐藏，且间隔恰好为 1 秒。
- 到期：未隐藏，且到期时间 ≤ 现在。
- 今日新卡：创建日（UTC）是今天。

复习总次数、今日复习次数不以本地卡片重算。它们等于上次与服务端对齐的次数，加上本卡组队列里尚未上传的复习条数。跨过 UTC 日之后、再次对齐之前，今日次数从 0 起，只加今天新产生的待上传复习。

统计包含全部本地卡片。出卡则会丢掉对不上词条的卡，两者可能不一致。

## 同步

每条待上传记录按顺序编号，先发生的先发。请求带 `Idempotency-Key`（该条记录的 ID）。

何时上传：

- 复习或隐藏之后：仅当待处理条数 ≥ 100。
- 不等满 100 条也会上传：进入已登录主界面、进入学习页、应用进后台或回前台、网络恢复、离开上述页面。
- 用户点同步状态：立刻上传，并忽略退避等待。
- 未联网：跳过上传。

单条结果：

| 结果 | 处理 |
| --- | --- |
| 成功 | 从队列删除。若这张卡没有更新的待上传记录，用服务端返回的调度或隐藏状态覆盖本地，并清掉「未确认」标记。 |
| 401 | 停止本批剩余记录。状态变为「需要重新登录」。已成功的记录已删除，但本批不再拉取复习次数。 |
| 400 | 标为失败，继续上传其他卡片的记录。 |
| 404 | 删除这条记录和本地卡片，继续后面的记录。 |
| 网络错误 | 本条进入退避（30 秒、2 分、10 分、30 分、2 小时，之后保持 2 小时），本批停止。 |
| 其他 HTTP | 本条同样退避，继续上传其他卡片的记录。累计 8 次 HTTP 错误后标为失败。 |

同一张卡的记录严格按先后上传：失败的记录或仍在退避的记录，会拦住这张卡后面的所有记录，保证旧调度不会晚于新调度到达服务端。其他卡片照常上传。

服务端忽略 `Idempotency-Key`，所以网络错误的复习请求可能已经生效。重发这类复习前，先读服务端卡片列表（每批每个卡组一次）：服务端卡片已是这条复习的调度，就据此确认、不再重发，避免复习次数记两遍；否则或读不到列表，照常重发。

失败的记录不会自动重发。用户可以在「同步失败」状态里**重试**（立刻重发，之后再发被它拦住的记录），或**丢弃**（保留本地卡片改动，被拦住的记录照常上传）。丢弃后若这张卡已没有其他待上传记录，就清掉「未确认」标记，之后的下载会重新更新它的调度。

本批每有成功记录的卡组，再拉一次卡组详情，只更新复习总次数和今日复习次数。拉取失败的卡组在应用未退出期间的下一次上传时重试。不用服务端卡片列表覆盖本地调度。

界面状态（已同步时不显示）：

1. 需要重新登录
2. 同步失败（队列里有失败的记录，或上传过程抛错）
3. 离线学习
4. 同步中
5. 待同步
6. 已同步

网络类失败和仍在退避的 HTTP 错误显示「待同步」或「离线学习」，不显示「同步失败」。

## 登出

队列为空：清掉该账号的离线数据和媒体，再登出。

队列非空时询问：

- **同步后退出**：立刻上传。全部成功则清数据并登出。仍有剩余则改为问保留还是丢弃。
- **保留并退出**：数据留在本机。同一账号再次登录后继续上传。
- **丢弃并退出**：连同未上传的复习一起删除。
- **取消**：不登出。

删除前先停掉正在跑的下载和上传，并等正在发出的请求结束，避免它们把已删除的数据写回来。删除单个卡组时同样处理该卡组。

离线库出错时不拦住登出。
