# 卡组与发现

🌐 [English](knowledge_base_decks.md) · [知识库](knowledge_base_zh.md)

学习者管理自己的卡组并进入学习。作者编写源卡组并公开发布。导入者拿到一份钉住版本的副本：进度在副本上，源卡组更新后可以选择跟进。未登录的人可以通过深链看某一套公开卡组的详情，导入和学习仍要登录。

客户端没有子卡组。

## 卡组上有什么

`Deck`（`lib/models/deck.dart`）是用户库里的一条记录。

| 字段 | 业务含义 |
| ---- | -------- |
| `id`, `name` | 标识和显示名 |
| `owner` | 用户名和邮箱。客户端不拿它做权限判断，改不了就看接口错误 |
| `fields` | 词条列名。只有源卡组能改、能排序 |
| `rate` | 每日新卡上限。创建默认 30，界面限制 1–1000 |
| `minInterval`, `defInterval`, `maxInterval` | 存在模型上。学习滑块不读它们 |
| `stats` | 卡数、词条数、未见、已学、到期、隐藏、今日新卡、复习次数 |
| `sourceDeckId` | 非空就是导入副本 |
| `sourceVersion` | 副本钉住的源发布版本。源卡组上为 0 |
| `publishedVersion` | 源卡组最新已发布版本。0 表示从未发布 |
| `visibility` | 模型有 `private` / `public`。创建不传这个字段。发布界面写死 `public` |

目录项 `CatalogDeck` 不是用户库里的那条卡组。它是公开快照：名称、可选描述、作者用户名、列名、版本、词条数、卡组标签名、发布时间。它的 `id` 是源卡组 id。

导入结果返回新的卡组 id、源 id、钉住的版本和导入时间。

## 列表与创建

我的卡组来自 `GET /api/decks`。客户端不排序，接口顺序就是展示顺序。接口没有分页；列表上拉在不足 20 条时结束，这是客户端的假分页。空列表有空态。失败可以重试。

点一张卡进入 `/study`，并带上这套 `Deck`。

创建从列表的浮动按钮进入：

- 名称 trim 后不能空。
- 至少两列，每列 trim 后不能空。列可以增删、拖拽排序。只剩两列时不能再删。
- `rate` 默认 30。
- `POST /api/decks` 只送名称、列名、每日配额。
- 可选标签在卡组创建成功后按差异调用标签接口。

## 编辑与删除

学习页菜单里的「编辑卡组」复用创建表单。

- 源卡组：名称、列名、配额、标签都能改。`PATCH /api/decks/{id}`。
- 导入副本：名称和列名禁用。提交只含 `rate`。标签变化不直接改源，而是写入待提交贡献。

删除在学习页菜单，要确认。

- `publishedVersion > 0` 的源卡组：客户端直接提示，不请求删除。服务端也拒绝。
- 从未发布的源卡组、导入副本：客户端允许删除。成功后刷新列表并离开学习页。

## 发布

入口在列表的分享按钮（仅源卡组）和学习页菜单。

- 第一次：`POST /api/decks/{id}/publish`，body 里 `visibility` 固定为 `public`。
- 已经发布过：先拉 `publish-preview`，用摘要说明相对上次发布改了什么，再发布。
- 成功后发现列表会刷新。版本号展示给用户。
- 对已发布源卡组，客户端大约每 60 秒看一次预览。有未发布改动时，列表角标闪烁。应用进后台会停，回到前台再开。

不能发布导入副本。没有改动时服务端会拒绝，客户端展示错误。

## 发现与导入

发现页 `GET /api/decks/catalog`，支持搜索和分页。筛选有「最新」和「收藏」。

收藏是本机 `SharedPreferences`（`discovery_favorite_ids`，存的是源卡组 id）。收藏筛选会按这些 id 再请求目录详情，在本地按搜索词过滤，没有服务端分页。

详情 `GET /api/decks/catalog/{id}` 免登录可看：名称、作者、词条数、发布时间、版本、列名、卡组标签、描述。

导入：

- 未登录 → 去登录。
- 已登录 → `POST /api/decks/import`，body 是 `source_deck_id`。
- 成功：提示，并刷新我的卡组。按钮变成去学习。去学习会再取一次新卡组详情。
- 失败：展示接口信息。已知包括不能导入自己的、源未发布、已经导入过。客户端不在点击前预检「是否已导入」。
- 离开详情再进来，按钮不会记住上次已导入，除非再次请求被服务端拒绝。

发现列表上的「已导入 / 不可用」展示位存在，当前列表没有接上数据，卡片一直按未导入画。

## 导入副本的更新

入口是列表上的刷新，或菜单里的检查更新。`GET …/updates?summary=1`。

- 没有更新：提示已是最新，同步按钮不可用。
- 有更新：展示版本区间和变更数量。单条词条可以再拉详情。
- 编辑或删除类冲突要选接受（`accept`）或保留本地（`keep`）。
- 同步：`POST …/sync`，带上目标版本和每条决定。成功后刷新列表。

「有更新」指最新源版本高于副本钉住的版本，或摘要里的变更计数不为空。源卡组再发布不会自动改副本。

导入副本大约每 60 秒查一次摘要，有更新则列表角标提示。
